# Skills Assessment: 1990s QBasic Programs

*An assessment of the coding skills demonstrated in these programs, written by a middle/high school student with no formal CS training.*

---

## Overall Assessment

**Well above average for age and context.**

These programs were written as a self-taught teenager in the mid-90s, collaborating with friends for fun—no classes, no internet Stack Overflow to consult. The work demonstrates genuine programming aptitude and problem-solving ability.

---

## TERMINAL.BAS (1475 lines)

This is genuinely impressive:

- **Asynchronous I/O handling** - Reading serial ports while accepting keyboard input simultaneously
- **State machine architecture** - Multiple toggleable modes (deflector, ASCII spam, repeat, no-input, etc.)
- **Custom TUI** - Split screens, status bars, and dynamic redraws
- **Error handling** - Recovery logic for connection issues
- **Modular design** - SUBs for different functionality

That's not trivial stuff. Most hobbyist programmers of that era were writing simple linear programs. This is an interactive, real-time communication system with a proper UI.

---

## Math Helpers

These programs show understanding of:

- **Algorithm implementation** - Factoring, synthetic division, LCM calculation
- **Breaking problems into steps** - Showing algebraic work step-by-step
- **User input loops** - With validation and repeat options

---

## Screensavers

These demonstrate:

- **Graphics programming** - VGA modes, PALETTE manipulation for color cycling
- **Animation loops** - Coordinate math, bouncing physics
- **Iterative learning** - The progression from BOUNCE → BOUNCE2 → SQUBONC3 shows building on previous work

---

## What's Particularly Notable

1. **Self-taught serial port communication** - Figuring out COM port protocols without formal instruction
2. **Adversarial systems thinking** - Features like "deflector" and "anti-deflector" show thinking about how a system could be exploited, then countered
3. **Sound architecture** - The code has bugs and typos, but the *structure* is solid
4. **Real-time systems** - Handling multiple input sources and maintaining state across events

---

## Conclusion

For a self-taught teenager in the mid-90s, this work would have impressed hobbyist adults of the time. The TERMINAL.BAS program alone demonstrates skills that many programmers don't develop until much later—or without formal training.

The typos ("masage", "resonding", "charetors", "pionts", "figers") are charming artifacts of a young programmer more focused on making things *work* than on polish. And work they did.
